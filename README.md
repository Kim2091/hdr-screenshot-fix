# hdr_screenshot_fix

A small Windows command-line tool that turns HDR screenshots into HDR PNGs that every viewer shows correctly,
including Discord. It uses only the Windows SDK (WIC). CRC-32, Adler-32 and zlib are written from scratch.

## Download

Get `hdr_screenshot_fix.zip` from the [Releases](https://github.com/Kim2091/hdr-screenshot-fix/releases) page.

## Usage

Drag one or more files onto `hdr_screenshot_fix.exe`, or run:

```
hdr_screenshot_fix [--no-pause] [--keep-cicp] [--dump-icc out.icc] file...
```

Each file is processed on its own. A bad file prints an error and the tool moves on to the next one. At the end it
prints `N converted, M failed` and waits for Enter so the console window stays open after a drag-and-drop.

- `--no-pause` skips the wait for Enter, for scripted runs.
- `--keep-cicp` keeps (PNG mode) or adds (JXR mode) a `cICP` 9/16/0/1 chunk for true-HDR viewers. It is off by
  default because some viewers, Discord among them, show PNGs that carry `cICP` blown out and yellow.
- `--dump-icc out.icc` writes the embedded ICC profile to a file so you can inspect it.

Existing files are never overwritten. If an output name is taken, a numbered name is used (`.hdr.2.png`, `.icc.2.png`, and so on).
The exit code is 0 when every file was converted and 1 otherwise.

## Modes

The input type is detected from the file contents, not the extension.

**JPEG XR (`.jxr`, NVIDIA app / Game Bar HDR captures).** The image is decoded with WIC as scRGB (linear, Rec. 709
primaries, 1.0 = 80 nits). It is converted to BT.2020 primaries, negative values are clamped to 0, alpha is dropped,
values are clamped to 10000 nits and encoded with the SMPTE ST 2084 (PQ) curve, then quantised to 16 bits. The output
is a 48-bit RGB PNG with these chunks: `IHDR`, `iCCP` (the PQ profile), `cICP` (only with `--keep-cicp`), `cLLi`,
`sBIT` (16 bits), `cHRM` (BT.2020 primaries, D65 white), then `IDAT` chunks of at most 64 KiB. There is no `gAMA`,
because PQ data is not a power curve. `cLLi` follows CTA-861.3: MaxCLL is the largest max(R,G,B) of any pixel and
MaxFALL the frame average of max(R,G,B), in nits of the encoded BT.2020 signal. The output is written as
`<name>.png`, or `<name>.hdr.png` if `<name>.png` already exists (the NVIDIA app saves a PNG next to each JXR).

**PNG with cICP 9/16/0/1** (HDR PNGs from the NVIDIA app or SKIV). Every chunk CRC is checked. Any `iCCP` or `sRGB`
chunk is replaced by the PQ ICC profile right after `IHDR`, and the `cICP` chunk is removed unless `--keep-cicp` is
given. Every other chunk (including `gAMA`, `cHRM`, `cLLi` and all pixel data) is copied byte for byte. If one `IDAT`
chunk is larger than 1 MiB, the pixel data is re-split into 64 KiB chunks; the compressed stream itself is unchanged.
The output is `<name>.icc.png`. PNGs without that `cICP` chunk (SDR screenshots) are skipped and left untouched.

## ICC profile

The embedded profile (`rec2100pq_icc.h`) is a libjxl-generated PQ ICC profile (desc `RGB_D65_202_Rel_PeQ`, 4344
bytes), included unmodified. Its own copyright tag states CC0, and that is the licence basis. It was extracted from
an HDR PNG written by SKIV (SpecialKO/SKIV, MIT), which credits ledoge/jxr_to_png (GPL-3.0) for it. That repository's
`icc_profile.h` says "Rec2100PQ.icc generated by libjxl" but holds a related 4324-byte profile, not this exact file.
It is an ICC v4.4 profile with a Lab PCS, an A2B0 lookup table that tone-maps PQ to SDR relative to about 203 nits,
and a `cicp` tag. `tools\extract_icc.py` regenerates the header from such a PNG. See `NOTICE` for the full chain.

## Build

Run `build.bat`. It finds the newest Visual Studio or Build Tools install with the C++ x64 tools (via `vswhere`) and
produces `hdr_screenshot_fix.exe` (static CRT, links `windowscodecs.lib` and `ole32.lib`).

## Tests

`tools\` holds the test helpers. Run the Python scripts with `python -I`; they use only the standard library.

- `verify.py`: checks chunk CRCs and order, that `cICP` is absent (or present with `--keep-cicp`), that `iCCP`
  inflates byte-identical to the NVIDIA profile, prints `cLLi`, decodes 16-bit PNGs to spot-check pixel codes, and
  compares a PNG-mode output's chunk list with a reference file.
- `extract_icc.py`: extracts the iCCP profile from a PNG into `rec2100pq_icc.h` and prints its desc and cprt tags.
- `make_test_jxr.cpp`: writes a small lossless scRGB JXR with known values, including negatives and values above 10000 nits.
- `jxr_ref_pixels.ps1` and `expected_pq.py`: read reference pixels from a JXR through WPF and compute the expected PQ codes.
- `compare.py`: compares a JXR conversion with the NVIDIA app's own PQ PNG of the same capture.
